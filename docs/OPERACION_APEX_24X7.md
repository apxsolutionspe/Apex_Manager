# Operaciones APEX PRIME X — 24/7 con límites y cobros verificables

**Configuración desde:** 21/10/2026 (hora de Perú). **Presupuesto comprometido:** S/0.

## Qué significa 24/7

La base es un workflow público de GitHub Actions ejecutado **cada hora nominalmente**, no un servidor siempre encendido ni cientos de agentes que deciden con dinero ajeno. GitHub puede retrasar u omitir ejecuciones programadas; hay límites de API y disponibilidad de conectores. El repositorio `apxsolutionspe/Apex_Manager` es público y usa `ubuntu-latest`, corredor estándar cuyos minutos no se facturan para repos públicos conforme a la documentación oficial vigente al momento de la configuración: https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job.

Cadencia de trabajo:
- **GitHub hourly:** ejecutar como máximo 3 consultas públicas de búsqueda de recompensas de código en paralelo, inspección de 4 destinos comerciales, ranking de 120 hipótesis y captura de evidencia efímera. **No** publicar en redes ni enviar mensajes.
- **Automatización de ventas ChatGPT:** exploración recurrente de demanda auténtica y mejoras de conversión usando herramientas conectadas que estén disponibles; informar solo contactos/recompensas confirmadas.
- **Automatización técnica:** resolver defectos de CotizaPro, CatálogoExpress y escaparate real, probar en PR y publicar tras CI.
- **Radar de bounties:** chequear source primaria, política IA, requisitos legales, financiamiento real y permiso para PR; sin reclamar ganancias hasta cobro.
- **Radar cripto:** solo lectura; nunca firmar transacciones, gastar, mover activos o confundir testnet y recompensa.
- **Auditoría comercial:** evitar Metricool y redes donde no se haya autorizado el acceso; orientar tareas a señales comerciales reales, no visualizaciones sin ventas.

## Herramientas conectadas: acciones permitidas

**GitHub:** construir, probar, versionar y publicar activos públicos bajo el repositorio autorizado; nunca publicar repos privados, API keys, tokens, archivos de cliente o datos sensibles.

**Canva y Figma:** crear diseños originales y editables para necesidades demostradas, con licencias adecuadas; no copiar/redistribuir materiales restringidos. Los archivos creados de APEX son un kit de 6 posts Figma y un pitch deck de 10 diapositivas Canva. Crear un recurso no es una venta.

**Shopify:** leer productos y pedidos si existe conexión, evitar duplicar productos y **no** activar suscripciones ni declarar pagos mientras el plan trial impida ventas. Las compras jamás se inventan.

**Wix/Lovable/Vercel/Render:** usar únicamente para mejorar un producto cuando el plan permita alojarlo sin cargos, duplicación o compromisos nuevos. No crear diez tiendas vacías.

**Mercado Pago Perú:** el titular habilitó `https://link.mercadopago.com.pe/apexprimex`. Es un link **sin importe definido**. El cliente debe aprobar por escrito precio, alcance, moneda, licencia y condiciones **antes** de ingresar manualmente el monto. Solo una transacción acreditada y conciliada permite reclamar ingreso. Esta automatización no tiene credenciales API Mercado Pago, no puede comprobar ni retirar saldo ni entregar producto automáticamente tras pago.

## Etapas de evidencia de un ingreso

`idea` → `asset_created` → `published` → `buyer_inquiry` → `quote_accepted` → `payment_pending` → `payment_accredited` → `delivered`.

**Regla de auditoría:** `payment_accredited` requiere datos autenticados del procesador o documentación aportada por el legítimo titular. Ni un link de cobro ni un PR de GitHub justifican incrementar ingresos verificados.

## Guardarraíles

- Sin gastar los S/20; no comprar dominios, publicidad ni suscripciones.
- Sin envíos masivos a desconocidos, spam, reseñas falsas, granjas de cuentas ni falsa identidad.
- Sin scraping que ignore controles de acceso, phishing, malware ni vulnerar plataformas.
- Sin crear cuentas de pago, concluir KYC o acceder a bancos en nombre de otra persona.
- Sin pruebas de pagos reales, transferencias, apuestas, trading, depósitos cripto o promesas de rentabilidad.
- En caso de prueba CI fallida, dejar PR sin fusionar; un fallo externo no es licencia para eludir controles.
- Evidencias técnicas de workflow en artefactos con retención de **3 días** y sin información bancaria o credenciales.

## Resultado comercial que importa

Indicador principal: **pagos acreditados** y servicios entregados. Secundarios: clientes voluntarios, cotizaciones aceptadas, rebotes y fallos de páginas. Indicadores de actividad (issues vistos, agentes nominales, hipótesis, archivos creados) no son ingresos.
